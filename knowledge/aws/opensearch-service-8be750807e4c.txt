Amazon OpenSearch Service
Resolve FIPS endpoint connectivity issues in private hosted zones
FIPS endpoints work with Amazon OpenSearch Serverless collections that have public access. For newly created
        VPC collections that use newly created VPC endpoints, FIPS endpoints function as expected.
        For other VPC collections, you might need to perform manual setup to ensure FIPS endpoints
        operate correctly.
To configure FIPS private hosted zones in Amazon Route 53
Open the Route 53 console at
https://console.aws.amazon.com/route53/
.
Review your hosted zones:
Locate the hosted zones for the AWS Regions your collections are
                        in.
Verify the hosted zone naming patterns:
Non-FIPS format:

.aoss.amazonaws.com

Common Issues
If you experience connectivity issues with your FIPS-compliant VPC endpoints, use the
            following information to help resolve the problem.
DNS resolution failures - You cannot resolve the FIPS endpoint domain name
                    within your VPC
Connection timeouts - Your requests to the FIPS endpoint time out
Access denied errors - Authentication or authorization fails when using FIPS
                    endpoints
Missing private hosted zone records for VPC-only collections
To troubleshoot FIPS endpoint connectivity
Verify your Private Hosted Zone configuration:
Confirm that a Private Hosted Zone exists for the FIPS endpoint domain
                            (
*.region.aoss-fips.amazonaws.com
.
Verify that the private hosted zone is associated with the correct
                        VPC.
For more information, see
Private hosted zones
in the
Amazon Route 53 Developer Guide
, and
Manage DNS
                            names
in the
AWS PrivateLink Guide
.
Test DNS resolution:
Connect to an EC2 instance in your VPC.
Run the following command:
nslookup collection-id.region.aoss-fips.amazonaws.com
Confirm that the response includes the private IP address of your VPC
                        endpoint.
For more information, see
Endpoint policies
, and
DNS attributes
in the
Amazon VPC User Guide
.
Check your security group settings:
Verify that the security group attached to the VPC endpoint permits HTTPS
                        traffic (port 443) from your resources.
Confirm that security groups for your resources permit outbound traffic to
                        the VPC endpoint.
For more information, see
Endpoint policies
in the
AWS PrivateLink Guide
,
                and
Security
                    groups
in the
Amazon VPC User Guide
.
Review your network ACL configuration:
Verify that network ACLs permit traffic between your resources and the VPC
                        endpoint.
For more information, see
Network ACLs
in the
Amazon VPC User Guide
.
Review your endpoint policy:
Check that the VPC endpoint policy permits the required actions on your
                        OpenSearch Serverless resources.
For more information, see
VPC
                            endpoint permissions required
, and
Endpoints policies
in the
AWS PrivateLink Guide
.
